## 2. Reviewer INFORMATIONAL residuals — all remain OPEN for an optional, short V1.2 addendum before any candidate study

**N1-a — missing trusted RELEASE PUBLISHER ROOT purpose.** V1.1 registry has a PUBLISHER_WITHDRAWAL_SIGNER (E:49) but no PUBLISHER_RELEASE_ROOT signer of source/template/renderer/worker+validator pins; current phrase 'root checked against same source publisher' can be circular if neither is independently anchored. Distinct external publisher root evidence/pins and separate withdrawal purpose must be explicit.

**N1-b — missing protected terminal-event issuers.** The 'Complete' register lacks ABANDON, REVOKE, RECOVERY and COMPLETE/COMPLETION issuers. R3:127–128,141 require separately purpose-bound authenticated terminal events; without these Q may stay pending FOREVER, fail-closed but unusable. Do not let CAS, current E/W or model narrative manufacture terminal authorization.

**N1-c — CAS executor not registry authorizer.** Same protected store may APPLY root-signed mutation atomically to H_n epoch/nonce/revocation but is NOT itself empowered to AUTHORIZE any role-key/root update. Split signed authorization from its transaction execution and distinguish each root/key purpose.

**N1-d — key vs custodian separation.** Distinct root signing key is necessary but not proof that an attacker who compromises the CAS/E/W service cannot access root/recovery custody. Require independently protected custody boundary (or explicit T2/T3 residual/refusal) before candidacy.

**N1-e — permitted bootstrap anchor classes unproven.** Enumerate independent anchor evidence classes (externally authenticated hardware-root provenance, independently secured out-of-band manufacturer/publisher key enrollment, separately protected quorum from pre-existing root) as HYPOTHESES, not available selected roots; local trust-on-first-use/DPI Git SHA not accepted.

**N1-f — recovery quorum purpose and PERSONAL practicality.** Define whether separately rooted quorum may ROTATE_ROOT vs only role mutation, root-loss/lost quorum fail-closed outcome, and whether real single user could satisfy physical quorum without imaginary enterprise administrators. No quorum currently selected.

**N1-g — monotonic registry epoch witness and trusted mutation UI.** Define which truly T2-independent durable store/observer witnesses head/registry epoch freshness and rollback refusal; the authenticated UI for editing role keys cannot be hosted by the role/key whose authorization it changes.

**N-2 remaining:** immutable vendor endpoint/TLS pin ROTATION owner/ceremony remains undefined. Grade-B protected Fable wrapper cannot let CurrentUser CA/proxy or a same-user role mutate a pin silently; protected register/publisher authority and revocation must govern any trust-anchor change.

**N-3 remaining:** P01/P03/P06 'proof of protection' is partly circular; 'credible issuer' not defined. P05 clock uncertainty budget and P11 ceremony/cost ceiling require future explicit user/product thresholds; vendor documentation alone cannot satisfy any gate. Provider version change must trigger complete re-adjudication, and a real independent human/security adjudicator/principal has not been selected nor its cost/availability proven.

**N-4 remaining:** source Git-object staged from *caller-provided commit in local repo*, no independent root or signature (release_artifact.py states it does not authenticate a publisher). Later verify of v2 does NOT reauthenticate byte mode, git_blob, source_commit/source_tree or publisher, only self-consistent file bytes/hash and allowlist. Neither stage nor verify grants a trusted Opus artifact.

**N-5 remaining:** explicitly enforce **ANY mismatch with independently completed G blocks E, V, CAS and W** until separately approved governed release transition, including non-policy updates that change source/release/pins/loader. Clarify 'as appropriate': pin/template/renderer/allowlist changes need explicit trusted operator disclosure and prestate-protected validation. With Q=PENDING/RECOVERY a routine release must refuse. Distinguish candidate stop vs entire F1-program stop; inventory and REAL single-user costs of H0 enrollment, E proposal, V, W installation, key rotation, abandon/recovery, and every routine release update. This may be inherently disproportionate; a documented BLOCKED result is legitimate.
