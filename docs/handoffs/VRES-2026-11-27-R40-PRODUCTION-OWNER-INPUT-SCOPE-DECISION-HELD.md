## 2. Targeted production authority result

Current requirements simultaneously require one production interactive Windows user, deny both contained model processes and ordinary uncontained same-user impersonation, independently deliver the full exact transaction proposal and bind a fresh actual human response, and preserve original updater and continuous original lock. Existing noninteractive broker design can isolate execution but alone cannot attest human input. A user SID/logon/session, nonce, process PID, or confirmation boolean is not a trusted proof of human intent. Ordinary same-user input cannot simply be declared trusted. Guest cross-user/session success cannot establish one-login production proof.

Targeted public platform verification, not a Windows test:
- [Microsoft security servicing criteria](https://www.microsoft.com/en-us/msrc/windows-security-servicing-criteria) recognizes process, user, session and AppContainer boundaries; administrator controls OS TCB, UAC is not robust isolation against a malicious administrator. [UAC](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works) protects elevation, not arbitrary application transaction-specific consent.
- [Desktop security/access rights](https://learn.microsoft.com/en-us/windows/win32/winstation/desktop-security-and-access-rights) and [SwitchDesktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-switchdesktop) support ACL-controlled desktop activation. This could isolate input with a separate trusted renderer; no authenticated owner entry/complete display/input chain or production protected renderer is established. Do not equate creating a separate desktop with a trusted-attention mechanism; no unsupported Winlogon customization, driver or policy weakening.
- [CredUIPromptForWindowsCredentials](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-creduipromptforwindowscredentialsw) documents CREDUIWIN_SECURE_PROMPT for a credential dialog on secure desktop and a returned authentication buffer; [CREDUI_INFO](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credui_infow) allows a caller-provided brief message/caption. This is not established as an independently authenticated, complete proposal/reply contract for Vres-OS. It does not by itself prove trusted origin, full exact rendering or operation binding; no real credential collection, enrollment or validation authorized. No assertion that every possible secure desktop construction is impossible.
- [Windows UserConsentVerifier](https://learn.microsoft.com/en-us/uwp/api/windows.security.credentials.ui.userconsentverifier) and [RequestVerificationAsync](https://learn.microsoft.com/en-us/uwp/api/windows.security.credentials.ui.userconsentverifier.requestverificationasync) provide device authentication, caller-supplied message, verification result. No proof in retained design of independent renderer, exact transaction binding and ordinary same-user impersonation denial. User verification or presence alone is insufficient.
- [Android Protected Confirmation](https://developer.android.com/privacy-and-security/security-android-protected-confirmation) documents a real example of attested hardware-backed signing of displayed confirmation text plus fresh request data on supported devices. This shows an independent trusted transaction display/input is technically plausible, not that any retained device supports it or that a Windows-only Vres-OS integration is available. Additional device/software/enrollment/transport and attestation/complete display evidence would require explicit approval; no new external app/device, credential or route assumed. Ordinary FIDO/Hello presence is not substituted for trusted transaction display.
- Existing two-guest-session candidate remains a valid conditional cross-user/session architecture, not proof for one production login. Actual secure-attention console, distinct guest standard/operator sessions, service token and exact runtime remain NOT_ESTABLISHED.
