## 2. PT2B behavior and strictly non-authoritative boundary

The new module is a pure deterministic, immutable **in-memory** change-journal/recovery model. Its only imports are standard-library hashlib and dataclasses plus the existing PT2A pure transition planner. No physical file, installed/current-user Claude configuration, environment, hook, PostgreSQL, credential, host, network, subprocess, backup, provider-model or database I/O is implemented.

PT2B uses exactly the PT2A logical roles managed / distribution. A fresh journal rejects modeled forward progress unless PT2A supplied a matching paired caller-before claim, both caller-only backup SHA256/length claims match each role's before digest/size, and the release-coherence input is explicitly ASSUMED_COHERENT_FOR_SIMULATION. Actual release v2 coherence is NEVER verified: UNKNOWN is blocked, and the assumption cannot become protected authority. Absent, outdated, divergent or malformed PT2A claims, missing or mismatched snapshots, wrong roles and unrecognized release statuses fail closed. The older installed original P2 source may differ from accepted current Git SOURCE, so ordinary PT2B simulation must never silently treat the older installed body as reconciled.

Events are ordered by sequence and a source/plan purpose-bound SHA256 fingerprint. Each carries both claimed prior and proposed after target digests. Deterministic replay models DRAFT -> STAGED -> PREPARED -> MANAGED_UPDATED -> BOTH_UPDATED -> SIMULATED_COMPLETE. Failure before any modeled write -> ABANDONED; failure after the first or second target -> RECOVERY_REQUIRED, followed by RESTORE_DISTRIBUTION -> RESTORE_MANAGED -> RECONCILE_BEFORE -> SIMULATED_ROLLED_BACK. Interruptions during recovery and digest-idempotent retries are simulated. UNCERTAIN halts terminally rather than inventing actual current target bytes. Replay refuses skipped/reordered boundaries, cross-plan events, incorrect hashes, illegal terminal transitions, ambiguous state and more than 32 events.

Every manifest **always** reports simulation_only=True, safe_to_install=False, installation=NOT_INSTALLED, operator_install_consent=REQUIRED_SEPARATELY, release_manifest_verified=False, trusted_paths_resolved=False, rollback_snapshot=NOT_CREATED, recovery_completed_on_host=False, effective_model=UNKNOWN, physical model not observed, and multi_target_atomicity=NOT_CLAIMED. Boolean conversion raises. An offline backup digest CLAIM is not a durable backup; no raw before-copies are retained, and no real restore is executed. A SIMULATED_COMPLETE or SIMULATED_ROLLED_BACK result is NOT proof of host write, actual rollback, signed F1 authority, release manifest integrity or consent. Python frozen dataclasses are not a trusted issuer.
