## Implemented E1 surface

### Immutable episode ledger

Migration:

`src/vres_os/migrations/037_experience_episode_ledger.sql`

Adds `vres.experience_episodes` with:

- versioned episode/policy identity;
- project/task provenance;
- task or work-unit origin;
- work-unit attempt identity so a failed attempt remains a failure after a later retry;
- participated/observed mode contract (E1 writer emits participated only);
- task-family, domain and capability applicability;
- objective/context/constraint/outcome/gotcha fields;
- existing procedure/decision/validation/source/artifact references;
- explicit trust class;
- observed time;
- source and payload SHA-256 digests over canonical sanitized JSON;
- explicit security disposition/flags;
- terminal-source validation trigger;
- immutable update/delete protection;
- unique task and per-work-unit-attempt origin constraints.

### Deterministic capture service

`src/vres_os/experience.py`

The public capture API does not accept caller-authored episode payload, trust,
outcome or security authority. It reconstructs experience from existing database
facts.

Security behavior:

- reuses the canonical #164 sanitizer before persistence or digesting;
- sanitizable credential material is stored only in sanitized form;
- residual credential-like forms fail closed and roll back the terminal lifecycle write;
- structured secret-bearing keys are redacted before digest calculation;
- hidden/private-reasoning field names such as `chain_of_thought`,
  `hidden_reasoning`, `private_reasoning`, `reasoning_trace`,
  `scratchpad` and `cot` are rejected recursively;
- instruction-like content is retained only as inert data with a bounded security flag;
- no remembered content becomes company authority, policy, permission, routing,
  validation or procedure state in E1.

Idempotency/concurrency behavior:

- origin-specific PostgreSQL advisory transaction lock;
- one immutable task episode per task;
- one immutable work-unit episode per `(task, work_unit_key, attempt_count)`;
- duplicate capture returns the existing row only when source/payload digests match;
- divergent recapture fails closed.

### Existing relation graph reused

`src/vres_os/relations.py`

The existing relation/evidence graph is extended with typed nodes for:

- episode;
- decision;
- capability;
- validation.

E1 writes episode provenance links to the existing task/decision/procedure/capability/
validation/source/artifact owners rather than creating duplicate authority tables.

### Lifecycle integration

`src/vres_os/repository.py` and `src/vres_os/routing.py`

Capture occurs in the same PostgreSQL transaction as:

- host-observed work-unit pass;
- host-observed work-unit failure/rejection;
- protected task completion;
- routine governed task completion.

If E1 safety/provenance capture fails, the terminal lifecycle write rolls back.

The existing lifecycle remains the owner of completion authority. In particular,
historical/grandfathered tasks that carry the old `validation_status='passed'`
projection without a `validation_requests` row still complete under the existing
contract. E1 records them without inventing validation provenance, therefore their
episode remains `trusted_project_source` rather than being mislabeled
`validated_runtime`.
