## Architecture / truth-owner rule

Retrieval reads the existing truth owners (knowledge, procedures, task decisions, E1 episodes, relations, sanitized chunks) and applies one eligibility gate. It creates no second memory store, no vector store and no retrieval log. Embedding results, when available, are re-resolved through the same gate.

## Retrieval authority and temporal behavior

- Authority and scope precede relevance. Only items meeting the contract's authority conditions may be `instruction`; proposed/observed items (including E2 lessons) are `candidate` only; untrusted observations never become instructions.
- Relevance, semantic similarity and recency are ordering signals, not truth. Newer is not truer.
- Conflicts, stale items, challenged items and premise mismatches are surfaced, not silently resolved.
- Temporal intent is explicit (`current` default, `historical` with optional `as_of`); superseded/expired items are suppressed under `current` and labelled under `historical`.
- Unapproved `project_id IS NULL` rows are excluded and counted; another project's rows are invisible.

## Raw fallback

Triggered only when no decision, accepted procedure or validated lesson survives, and disabled by `raw_fallback=false`. It is bounded lexical search over already-stored, sanitized chunks through the same eligibility gate, returned as low-trust `evidence_ref` items. No filesystem or network raw re-read is introduced and nothing is persisted.

## MCP surface

`experience_retrieve(request)` takes a request object; `project_id` is rejected and bound from the trusted session project. Fields: `query` (required), `task_key`, `task_family`, `capability_keys`, `temporal_intent`, `as_of`, `premises`, `include_candidates`, `raw_fallback`. Unknown fields are rejected. The tool writes and observes nothing.
