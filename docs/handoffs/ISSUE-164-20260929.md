## Threat model / contract
Legacy folders contain secrets (env files, credential files, keys, inline passwords/DSNs/tokens). Onboarding must
never persist or send to a model any such value (sources, chunks, embeddings, review queue, jobs, metadata, paths),
must stay read-only, and must fail closed when it cannot reduce content with confidence. This is a deterministic
pattern policy; it does **not** claim to detect every secret.

## Sensitive path rules (case-insensitive, path only, file never opened)
`vres_local_secrets` (`.vres` followed by `local-secrets` path parts) · `env_file` (`.env`, `.env.*`) · `secrets_toml` ·
`credentials_file` (`credentials`, `credentials.*`) · `auth_file` (`auth.*`) · `private_key_file` (`id_rsa|dsa|ecdsa|ed25519[_*]`,
suffixes `.pem .key .p12 .pfx .ppk .jks .keystore .pkcs12`). Existing pruning (.git, venvs, node_modules, caches, build/dist, .next,
site-packages, coverage) and symlink/junction exclusion are unchanged. Excluded files: `source_files` row with status
`sensitive_excluded`, NULL source/hash, only rule id + policy version + stat provenance. No hash, extract, chunk, embed, classify or review.

## Sanitization rules (`redaction.py`)
`kv_credential` (keys ending/containing password, passwd, pwd, api key, access/refresh token, client secret, private key, token, secret, with prefix ≤64 chars);
`uri_credential`; `bearer_token`; `provider_token` (sk-, gh*_, github_pat_); `private_key_block`. Dict keys are redacted by suffix. Idempotent.
Sanitizer metadata holds only rule names, counts and field names (no values).

## Fail-closed rule
After sanitizing, residual checks (private-key marker, credential-looking assignment ≥8 chars not redacted, AKIA/xox/AIza/sk_live/JWT shapes) mark the file
`sensitive_review_required`: empty text, no source row, no hash, no chunks/embeddings, generic review_queue item (priority 10).
Otherwise rule hits → `sensitive_sanitized` (sanitized text continues); none → normal flow.

## Credential Broker (#163) boundary
No new store, no Broker code change, no secret capture. Onboarding records non-secret field names only; storing a credential needs user-local hidden-input
Broker confirmation, never auto-confirmed by Chairman.

## Phase 2 addendum — embedding/network contract
- Embeddings are optional for basic ingestion and are the intended path to semantic retrieval. Onboarding is NOT documented or implemented as globally offline.
- With `embeddings_enabled`, extracted text is #164-sanitized first; only sanitized chunks are queued and encoded.
- `EmbeddingService._load_model(model_name)`: the model name comes only from `ConfigStore().load().embedding_model`. It tries `SentenceTransformer(..., trust_remote_code=False, local_files_only=True)` first, and only on a local cache miss (`OSError`) acquires the SAME model with `local_files_only=False`, `trust_remote_code=False`. Non-cache failures do not download.
- Downloading a model is separate from embedding documents; inference is local; no remote embedding provider exists. Project content (URLs, links, model names, workbook/PDF links) cannot select a model or cause outbound requests (`ingestion.py` imports no network code).
- Acquisition failure keeps onboarding and sanitized chunks; jobs stay pending, then `failed` after 3 attempts (failed jobs are NOT auto-revived by `queue_missing`; manual reset needed), bounded redacted error, never completed. `semantic_search` can also trigger acquisition of the same configured model. Reviewer findings (Medium retryable overstatement; Low OSError heuristic, fake-only acquisition path, search-path acquisition, doc wording) are addressed by documentation only; no code change.
- Tests: `tests/test_embedding_acquisition.py` (8) and the PG test `test_embedding_boundary_sanitized_local_encode_no_content_driven_network`.
- Unverified locally: `sentence-transformers` is not installed here, so the real `local_files_only` argument and the cache-miss exception type are covered by fake-module tests only; PDF/Excel link non-following is static evidence. A real first-run acquisition remains a live gate.
