### 1.1 Full mandatory purpose register (all NOT ENROLLED)

**PUBLISHER_RELEASE_ROOT** must be separately independently anchored and allowed to attest approved source/renderer/pins and versioned source/derived release manifests. **PUBLISHER_WITHDRAWAL_SIGNER** must attest revocation/withdrawal generation and never self-authorize new publisher or role keys. **E_PROPOSAL, V_PROTECTED_FABLE_VALIDATION, H_ANCHOR_CAS_NONCE_REVOCATION and W_INSTALLATION** are independent purpose-bound issuers from accepted V1/V1.1, not user prompts. **ABANDON_Q, REVOKE_Q, RECOVERY_Q and COMPLETE_Q** are explicit terminal-event issuers bound to exact Q/E/V/W/C/release/render, governing G, machine/SID/install and fresh head epoch; they may be implemented by independently guarded provider roles only under separately reviewed purpose separation, not caller-claimed task completion. **ROOT_REGISTRY_UPDATE and ROOT_REGISTRY_RECOVERY** remain distinct independently rooted authority; compromised CAS/E/W cannot change issuer verification keys. **D3_PROTECTED_INSTALL_LOADER and D4_HOST_MODEL_OBSERVER** are RESERVED/NOT ENROLLED; their mere presence in schema gives neither install permission nor physical model proof.

Each role record requires independently authenticated verification key/root chain, purpose domain/version, issuer principal, target/epoch/nonce, activation and revocation, allowed event schema and root-approved trust assumptions. No general "trusted issuer" boolean, local JSON self-signature, model assertion or hash matching is an equivalent. If ANY required role cannot be rooted and independently verified, positive #165/F1 model switch remains **BLOCKED**, even if typed source constructors all validate.

### 1.2 Realistic separation and cancel race

A single physical provider may host several logical services ONLY if actual T2-independent root and recovery custody is demonstrably isolated from CAS/E/W operation and their credentials. Domain-separated keys stored in the same compromised signing execution path are not independent. Protected CAS may execute root-signed registry changes in its linearizable transaction, but cannot mint those signatures. A CANCEL_REQUESTED may lose to APPEND_PENDING_CAS_COMMITTED; only a CANCEL_PROTECTED_COMMITTED outcome in the protected order cancels the pending proposal. If CAS wins, Q persists and a distinct protected ABANDON_Q/REVOKE_Q is required; do not replay consumed E or erase L history. Publisher withdrawal outside head store is not magically atomic with a filesystem write; future D3 per-use loader/protected final write protocol still blocked.
