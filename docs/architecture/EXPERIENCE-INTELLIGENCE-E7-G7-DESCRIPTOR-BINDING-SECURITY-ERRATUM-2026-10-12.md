# E7 G7 descriptor-binding security erratum (additive, 2026-10-12)

Status: **PROPOSED, not accepted** until an independent design review accepts it. It amends no earlier document (attestation contract, design-freeze errata, derived-staleness clarification stay byte-for-byte unchanged). Policy `176.g7.v1`, its dict and digest `f20b037b00d0a5711666fd6c1d98538101708d99e7f6f32cf5a490ff6b96cf03`, and migration 047 are not touched by this proposal.

## 1. Finding (confirmed, reproduced in PostgreSQL)
Migration 047 (`vres.source_trust_digests`) computes `descriptor_digest = sha256(utf8('source_type=' || coalesce(source_type,'') || E'\norigin=' || coalesce(origin,'') || E'\nversion=' || coalesce(version,'') || E'\nproject_id=' || coalesce(project_id::text,'')))`. Field values are not escaped, and `vres.sources` (001_initial.sql) has no CHECK/trigger on `source_type`, `origin`, `version`; `sources.py` only `strip()`s `source_type`. Two distinct tuples therefore serialize to identical bytes:

- A = (`report\norigin=vendor`, `external`, `v1`, 7) and B = (`report`, `vendor\norigin=external`, `v1`, 7): distinct tuples, identical canonical string, identical SHA-256 (offline Python proof). Likewise (`document`, `x\nversion=y`, `z`) vs (`document`, `x`, `y\nversion=z`).
- This is a serialization collision, not a SHA-256 collision.

Reproduction on the isolated PG 18.6 cluster against the uncommitted 048 reader (diagnostic test, not part of the candidate): grant issued for state A -> `verified_trusted`; the runtime role UPDATEs `source_type/origin/version` to B (fields verified changed); `source_trust_digests.descriptor_digest` is unchanged; `source_effective_trust` still returns **`verified_trusted`** for both collision families. Controls: a clean (LF-free) descriptor change is `unverified`; an explicitly revoked grant stays `unverified` under substitution.

Consequence: the reader can grant positive trust to a descriptor state that differs from the one the user approved. Classification: **product/contract defect in the frozen descriptor-digest definition (Chunk 1 / 047), inherited by the Chunk 2 reader**. It is not G8 (host ingress): the mutation is a plain runtime write to descriptor columns, independent of who authored the approval. Prior reviews recorded it as an out-of-scope limitation (VAL-c08e1ab8b7ca4ef8, VAL-0c47a21a33be462f); those validations remain accurate for their narrower tested scope.

## 2. Ambiguity inventory
With LF/CR-free values the 4-line serialization is injective over (source_type, origin, version, project_id) except for one equivalence: `coalesce(x,'')` makes NULL and `''` serialize identically for `origin` and `version` (`source_type` is NOT NULL; `project_id` renders as digits). Embedded LF is the only injectivity break among non-empty values. CR has no role in the serialization.

## 3. Option A - fail-closed reader restriction under 176.g7.v1 (recommended)
The predicate is added to the uncommitted 048 reader definition itself; no new migration; 047 is not edited. Add one reader condition: `verified_trusted` additionally requires that `source_type`, `origin`, `version` contain no CR or LF, evaluated null-safely, e.g. `AND coalesce(s.source_type,'') !~ E'[\\r\\n]' AND coalesce(s.origin,'') !~ E'[\\r\\n]' AND coalesce(s.version,'') !~ E'[\\r\\n]'` (a bare `!~` would yield NULL, hence unverified, for NULL origin/version and wrongly deny clean sources).

Properties: it can only turn a result into `unverified` (same class as the existing conservative conditions); the policy dict, digest definition, 047, and existing grants for clean descriptors are unchanged; a grant issued for an LF-containing descriptor never yields positive trust (fail closed; re-registering a clean source needs its own grant). On the LF-free domain digest equality is equivalent to descriptor equality, which is exactly the binding the contract assumes. Reading: policy `descriptor_change=requires_new_authorization` is interpreted over descriptors in the canonical LF/CR-free domain; outside it trust is not available at all. This is a reading of existing semantics (cf. derived-staleness clarification section 8), not a dict change.

Residual, to be accepted explicitly or rejected by the reviewer: (a) the 047 issuer can still record a grant for an LF-containing descriptor; harmless to the reader but a ledger row exists; (b) NULL vs `''` for `origin`/`version` remain digest-equivalent. Under `176.g7.v1` the descriptor identity is (`source_type`, `coalesce(origin,'')`, `coalesce(version,'')`, `project_id`) per the frozen dict line `descriptor_digest ..._null_as_empty`; NULL and `''` are the same normalized absence with no authority difference. Option A does not enforce exact raw-field identity between NULL and `''`; a flip between them is not a material descriptor change and needs no new authorization; (c) an issuer-side rejection or an injective digest requires Option B.

## 4. Option B - new injective format (new policy version)
A length-prefixed or canonical-JSON descriptor serialization with a new policy version/digest (e.g. `176.g7.v2`), a new 0xx migration for digest/issuer functions, compatibility planning for existing `176.g7.v1` grants (they would not satisfy v2; no reinterpretation of history), new subject-key shape, new protected validation of the policy dict, and re-issuance of grants. Closes (a)-(c) but is a larger frozen-contract change and not required to close the confirmed bypass.

## 5. Recommendation
Option A, provided the independent design review accepts that (i) it closes the demonstrated bypass on the whole LF-free domain, (ii) residuals (a)-(b) are acceptable under G7 v1, and (iii) it does not require a new policy version. If the reviewer finds Option A insufficient, work stops and the exact conflict returns for Option B; nothing is implemented before acceptance. Implementation scope after acceptance: only the 048 reader predicate and regression tests, which must include: (a) both collision families (type_origin: (`report\norigin=vendor`,`external`,`v1`) vs (`report`,`vendor\norigin=external`,`v1`); origin_version: (`document`,`x\nversion=y`,`z`) vs (`document`,`x`,`y\nversion=z`)): the 047 issuer records the grant for state A (one ledger row, replayed=false); the amended reader returns `unverified` for state A before any substitution, `unverified` after the runtime-role substitution to B with the fields asserted changed and `source_trust_digests.descriptor_digest` asserted unchanged, and `unverified` after a re-grant attempt on B (issuer replays the same row, ledger length unchanged); the pre-fix `verified_trusted` behaviour is historical evidence, not a positive control for these states; (b) positive controls on clean sibling sources: default descriptor, origin AND version NULL, origin AND version `''` -> `verified_trusted`; (c) restricted descriptors, each granted through the issuer and each `unverified`: CR or LF in `source_type`, in `origin`, or in `version` (each field separately, including LF in `source_type` with NULL origin and version, and CR-only in `origin`), with NULL-safe predicates and a clean sibling positive control for every denial; (d) clean change `unverified`, exact restore `verified_trusted`, ledger revoke `unverified` and not undone by restore; (e) NULL<->`''` flip of origin or version after a valid grant stays `verified_trusted` (pins residual (b) as intended); (f) the complete existing Chunk 2 matrix in `test_g7_source_effective_trust.py` (revoked grant, inactive/revoked source, company scope, foreign project, zero chunks, corrupt ledger rows, unknown policy identity, wrong content digest, `external_untrusted_observation` label, expiry=none, grant/revoke event resolution, role boundary, STABLE SECURITY DEFINER read-only, search_path, boundary activation, 047 SHA-256 pin and policy-digest pin) passes unchanged against the amended reader in the same isolated-cluster run; each denial is preceded by a positive-control grant on a clean state where applicable. Then focused PG runs, a new exact manifest and one fresh protected validation.
